# 可控 Solar System 重建设计

日期：2026-10-16。设计基线：v0.2.33。状态：用户已确认推荐路线并要求制定、执行分阶段计划；首版为源码、配置、调试接口可控，不含网页编辑器。

## 目标与验收含义

在当前仓库构建独立的 Next.js + React + TypeScript + Three.js Solar System。保留 NASA Eyes 的功能与视觉对照目标，首版提供源码、配置、调试接口的完整控制；用户已明确首版不需要网页编辑器。优先完成 Solar System，不同时启动 Eyes on Earth/Exoplanets。

新应用直接运行本项目编写和维护的模块；不能 iframe、重定向或动态加载恢复的 `eyes` 应用来完成业务。恢复源码只供研究和差分验证。Three.js 与官方 loader/codec 是列明版本、许可证、来源的外部依赖，不宣称自行编写。

“完全可控”验收为：天体/场景/故事来自有 schema 的配置；时间/相机/图层由公开命令控制；资源来源和缓存可检查、可替换、可清除；模块可单测和独立释放；功能状态与已知缺口可从文档追溯。默认资源仍使用 NASA 的精确运行时 URL，不承诺外部服务断网时全功能可用。

## 路线选择

| 路线 | 收益 | 限制 |
| --- | --- | --- |
| **独立模块重建，逐项迁移（推荐）** | 明确领域接口、纯数据求值、独立资源生命周期；可用恢复应用对照；可复用已验证纯算法 | 初期需要先建数据/时间/资源基础，再达到界面功能对齐 |
| 在恢复 Eyes 上持续拆分 | 初期功能保留最多 | barrel/global/注册与渲染耦合仍重；很难证明新系统已摆脱恢复运行时 |
| 扩展现有 SolarViewer 单体 | 最快产生一个自己的画面 | 当前只有 orb、无真实姿态与跨段加载、单面贴图等缺口会累积；不是完整基础 |

推荐第一条。现有纯解析和数学代码按审计结果迁入，不能整段复制单体场景后改名了事。

## 三个区域与切换规则

- `eyes/`：研究与行为对照，继续能独立构建运行，保留来源与许可证。
- `src/`：新应用的唯一业务源码。新增 `/explorer` 入口，在正式切换前可独立访问；研究对照仍在 `/eyes/index.html`。
- `docs/eyes-analysis/`：证据、逐模块合同、依赖和功能对照表。`docs/superpowers/` 保存设计及后续实施计划。

最初不改首页重定向。新系统达到 Solar System 验收矩阵且通过用户实测后，首页再切换到 `/explorer`。旧应用始终明确标成参考，不以它的功能截图作为新系统完成证据。

## 模块边界

目录名是拟议边界，实施计划应按现有约定细化；以下职责与依赖方向是约束。

| 模块 | 职责与公开合同 | 依赖与禁止项 |
| --- | --- | --- |
| `domain/time` | UTC/显示与源 ET 转换；仿真秒/实秒；暂停/实时/倍率/跳转；可注入单调时钟 | 不访问 DOM、React、Three；不通过 Date.now 隐式推进纯求值 |
| `domain/catalog` | 联合源目录/场景/工厂配置，产出 schema 校验后的实体、阶段、组件、资源描述 | 数据保留来源和版本；不用路径字符串猜全部父天体关系 |
| `domain/ephemeris` | 解析五种 dyn 点类型及索引；按实际覆盖区间求值位置、速度、姿态；声明外推策略 | 纯算法；不 import 恢复 Eyes；不依赖 Three；未知/无数据返回显式状态 |
| `domain/entities` | 实体阶段、父链、局部→世界变换、有效期、依赖拓扑及循环诊断 | 接收统一时刻与星历结果；不写 Three 对象；不把未知位置变成原点 |
| `runtime/resources` | 并发调度、取消、去重、重试、预算、缓存、资源租约、codec worker | 可注入 fetch/存储/decoder；取消与迟到结果必须归还；不批量镜像资源库 |
| `runtime/simulation` | 统一帧事务：时间→阶段→数据就绪→实体求值→相机→渲染快照；产出可检查状态 | 不让 React 与渲染器各自维护不同仿真时间；求值结果不可偷偷改时间 |
| `render/three` | 自有 RenderWorld、相机、几何、材质、LOD、拾取、GPU 生命周期；Three 官方 ESM | 只消费渲染快照/资源租约；不执行业务路由和故事状态机；无全局 Pioneer |
| `features` | 搜索、导航、时间、图层、信息、测量、比较、事件、观测与故事，用命令组合领域能力 | React UI 与动作流程分离；不直接遍历渲染器内部修改材质或时间 |

React 页面负责挂载、布局和可访问交互；Next 服务端提供配置、允许的资源边界与部署，不参与逐帧动画。WebGL 和 worker 只在 client boundary 内创建，SSR/import 期间不访问 window/document。

## 数据与坐标合同

配置版本必须显式存在。实体至少保留稳定 ID、内容元数据、时间分段父关系、控制器集合、组件描述、资源引用、有效区间和来源定位。控制器分别描述位置与姿态；不能继续把 allDynamo 拍平成“一个主轨道”。

领域长度统一为 km、速度 km/s、角度 rad；所有 ET 数值都有清楚的时间标尺。源二进制的字段顺序以真实夹具及恢复 Reader/Point 实现核对，已知的四元数 w/x/y/z 磁盘顺序与 Three.set(x,y,z,w) 通过具名结构适配。解析器不能只凭剩余字节整除就声称格式完全验证。

`orb`、`pos`、`lin`、`ori`、`quat` 分别实现目标控制器的采样、插值、传播和区间外策略；算法取自具体恢复控制器的证据，不把 nearest-element 推进冒充全部插值。索引最后一个时间可能是终止哨兵，实际可下载段数必须按已验证源合同解析，禁止请求多出的段。

控制器切换、父天体切换和实体存在性在同一求值事务中计算，正向、倒向与跳转共用阶段选择。父链有循环/缺父时返回诊断；不静默用一个错误轨道画在父天体中心。

新 Three 相机使用标准 -Z 投影与自有相机 rig；领域世界轴不因相机约定改变。Eyes +Y 相机作为对照时通过明确的姿态/投影适配验证。旧 shader 中自定义 w/depth 协议不能直接混入标准 Three 投影，需要统一重写适配并以数值和图像验证。

GPU 使用相机相对位置，领域仍保留高精度世界求值。首版评估标准材质的 logarithmic depth 与自有 shader 的同一深度写入；近远裁剪、极大距离与选中细节必须有量测。星空只依方向渲染；无数据实体不参与拾取。若统一深度不能满足场景，才引入列明所有权的多深度段，不能混用不同深度公式却称为一致。

## 资源、解压与缓存

资源描述保留确切源 URL、类型、版本、预期解码器和预算。NASA 媒体仍运行时按需请求；仓库只保留小型 dyn 测试夹具，禁止遍历下载整库。

缓存分层：网络响应缓存、已解析 dyn 的真实 segment 缓存、解码结果缓存、GPU 租约账本。每层记录 key、字节、最后使用、持有者和淘汰条件；不可把“清空 Map”当作已取消任务。失败 Promise 不永久污染缓存；共享请求按订阅者取消，不因一个视图退出而取消其他持有者。

索引缓存与段缓存分开；段键包括数据版本、控制器和实际段 ID，跨段重新查询覆盖。下载、解析、解压和实例化均有请求代次；视图退出或 seek 后迟到的旧结果不能附着当前场景。

官方 codec 的 JS/WASM 路径和哈希写入独立 manifest，明确是下载/缓存的第三方发布物。编译后的 WebAssembly.Module 可按能力缓存；解压后的数据可按预算存入浏览器持久存储，并提供清理/失败回退。持久化 API 不可用时退到内存；此策略不自动扩展为服务器资产镜像或完整离线资源库。

## 状态、命令与调试

单一应用状态记录选中实体、时间模式、相机模式、图层、面板和故事活动实例。高频帧数据不经 React 每帧全量重渲染；界面通过订阅采样读快照。

命令至少覆盖：时间 seek/play/pause/rate/live、实体 select/focus、相机 orbit/follow/reset、图层 toggle、故事 start/stop、资源 retry/clear。命令校验参数与可用性，并产生可追溯结果；URL 解析、按钮、故事和调试接口调用同一个命令入口。

调试入口按配置显式启用，开发默认可用，生产默认关闭可变命令面。可读内容包括实体阶段/父链、局部/世界/相机相对位置、姿态与数据覆盖、请求队列、缓存/资源租约、Three render.info、当前命令及错误。使用已声明类型接口，不提供 eval/任意执行字符串。只读 snapshot 和显式推进状态的确定性 step 可以用于测试；后者使用注入时钟与资源响应，不发真实网络请求。

## 分阶段实施与通过条件

这是程序顺序，不是每阶段完成就宣称整套 Eyes 已重建。

1. **分析闭环**：792 个剩余条目逐路径归类；14 个部分匹配文件保留边界；每个功能写出输入/状态/单位/失败与资源所有权。修正旧分析中的事实错误，留下仍未证明的条件。
2. **基础核心**：明确时间标尺；五类 dyn 求值、索引覆盖、阶段/父链和资源调度独立于 UI。用固定夹具、双向 seek、失败重试/取消/共享租约证明合同。
3. **独立运行入口**：`/explorer` 只用自有领域/运行时/官方 Three。展示真实地球、月球和一艘跨父阶段航天器，含姿态、选中/焦点和真实数据就绪；不加载恢复 Eyes JS。
4. **渲染能力迁移**：逐组件移植六面表面、LOD、模型、轨迹/粒子、星空、大气、环和深度/遮挡。每项同时做数值、资源和参考图像验收。
5. **交互与流程对齐**：替换模板和旧管理器，以同一命令系统实现导航/分享/信息/图层/工具/事件/故事，检查取消与状态恢复。
6. **整体验收与默认切换**：功能矩阵全部列出结果；指定视口/固定时间/固定相机图像对照，完整独立构建、关键对象与故事测试、长时资源观察；用户实测通过后再切首页。

不预填无法证实的帧率、视觉误差或工期。实施前选定可重复的目标设备、视口、固定时间和关键场景，记录基线再设通过阈值；验证条件写入计划，不能用“看起来差不多”代替。

## 验证分层

- 纯算法：真实小夹具、坏头/截断/无效类型、边界时刻、四元数、时间转换、正反阶段及父链。
- 服务合同：并发去重、取消语义、失败后重试、段缓存碰撞、LRU预算、最后持有者释放、过期结果不得挂载。
- Three 集成：真实 Three 几何/材质、相机投影、拾取/遮挡、深度/颜色、模型与 codec、共享纹理所有权及 dispose。
- 浏览器端到端：直接进入 URL、刷新/返回/分享、时间跳转、快速切目标/路由退出、story中断、resize、资源故障、context loss。
- 独立性检查：新运行入口不 import `eyes/src`，不请求旧 app bundle，不依赖 Pioneer 全局；关闭参考入口后新系统仍可运行。
- 发布：按现有版本规则验证 `npm ci`、测试、check、build，提交与标注 tag；正常构建绝不运行源码恢复工具。

## 当前不确定性与决策边界

已分析的静态行为不等于全部浏览器/GPU/宿主边界已运行验证。仍需落实的具体风险包括第三方 worker/解压失败传播、WebGL 深度一致性、完整动态实体配置、地形/模型细节和外部内容变化；每项须在对应实施阶段形成证据。

首版不做网页编辑器、账户/云同步、其他 Eyes 应用、NASA 全库镜像；后续扩展通过同一配置与命令接口加入。这里的范围不能用来删减 Solar System 的已承诺功能。自有系统不必复制上游已确认的错误，但行为差异必须写明原因与验证。

## 已确认的路线

用户已确认推荐路线：**当前仓库独立新增 `/explorer`，自有 TypeScript 领域与运行时 + 官方 Three.js + Next/React UI；先完成分析/基础核心，再逐项对齐 Solar System；首版包含源码/配置/调试接口，不含网页编辑器。**

用户已确认此路线；后续细化可执行的分阶段实施计划并编写新运行时代码。现有 NASA UI 参照和数据来源约束继续有效。
