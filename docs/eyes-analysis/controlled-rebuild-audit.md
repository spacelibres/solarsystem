# 可控新系统：现有工程审计与证据入口

基线：`9f14926`（v0.2.33）。目标是先理解行为，再用我们维护的 TypeScript、Next.js、Three.js 重建；恢复源码是对照材料，不作为新系统的业务运行时。

## 首版“可控”的范围

用户已选择：完整源码、配置和调试接口；首版不包含网页中的天体/轨道/故事编辑器。继续以 Solar System 为先，其他 Eyes 应用在此基础稳定后另立需求。功能与 NASA Eyes 的对照沿用此前要求；新系统不能仅有八个行星和能转动的相机便宣称完成。

“可控”包括可追踪数据来源、时间与单位、可替换资源源、可取消下载、可检查缓存和 GPU 资源、可独立测试模块，以及有明确输入输出的交互命令。它不等于 NASA 的远程资源必然在线，也不等于第三方 codec 的原始 C/C++ 源码由本项目编写。

## 当前 `src/` 不能直接当成完整替代品

以下结论来自实际源码。分清静态发现和已执行的探针，避免把旧注释中的期望当成已实现功能。

| 事实与位置 | 对新系统的影响 | 证据等级 |
| --- | --- | --- |
| `src/app/page.tsx` 将首页重定向到 `/eyes/index.html` | 当前默认展示仍是恢复应用；新系统必须有独立 Next 路由与运行入口 | 直接源码 |
| `SolarViewer.tsx` 在加载结果中过滤出 `kind === 'orb'`，仅将其送入场景 | `pos/lin/ori/quat` 虽有解析结构，尚未贯通运动与姿态求值；不能据解析器存在宣称支持全部轨道 | 直接源码 |
| 启动加载只用 `e.dynamo` 和固定 `START_TIME`；`setTime` 更新时间、使树缓存失效并更新位置，但不重载 dyn 窗口 | 跳时间、跨索引窗口、跨航天器父天体阶段时需要重新解析活动控制器与数据窗口 | 直接调用链 |
| `solar-scene.ts` 的 `entityOrientation()` 恒返单位四元数 | 自转、姿态、局部部件和日照计算需要真实姿态链；不能继续作为完成项 | 直接源码 |
| `solar-scene.ts` 约 1,510 行，同时拥有加载回调、场景、相机、输入、轨道、标签、特效和调试 | 不宜继续把所有职责加进一个闭包；应按模块与资源所有者拆分 | 结构与调用关系 |
| `surface.ts` 用 `$FACE=0` 的一张面贴图给球面；所有 surface role 都设置 sRGB | 六面投影与 LOD 需要按真实资产拓扑实现；normal/specular 等数据贴图的色彩处理需单独核对，不能一律当彩色图片 | 直接源码；视觉误差尚未量测 |
| `TimeBar.tsx` 的播放态显示“Real Rate”，但默认速度是 1 day/s | 时间 UI 应显示实际仿真秒/实秒；LIVE 应由时间是否跟随当前真实时刻决定 | 两模块直接调用链 |
| `clearDynamoCache()` 只清两个 Map，不取消已排队/进行中的下载；加载失败后没有自动移除 reject Promise，需显式 clear 才能重试 | 新资源调度需要 caller 取消、重试策略、失效代次、任务清理和资源租约 | 直接源码 |
| 场景 dispose 主要遍历几个顶层集合；云层/环子网格、独立大气层和纹理没有统一租约账本 | 需要明确共享/独占资源的释放责任，补 mount/unmount 和迟到加载验证 | 静态所有权缺口；未声称量测全部泄漏 |

### 已执行：分段缓存可返回错误窗口

研究探针把实际 `src/lib/dynamo/loader.ts` 通过本地 esbuild 打包，在 VM 中提供合成的 index/segment 响应。没有向 NASA 发请求，也不以合成数据证明新格式。

索引起点 `[0,10,20,30]`，每段两点分别覆盖 `0..9`、`10..19`、`20..29`。依次请求时刻 `[0,15,25]`，实际收到首点时间 `[0,10,10]`：第三次仍拿第二段，不能覆盖 25。原因是 `loadSegmentWindow` 以 `path@floor(time/(90*86400))` 为键，并直接返回该桶内的已缓存 Promise，没有再检验实际段覆盖范围。两个真实段边界完全可能落入同一个粗时间桶，故新实现必须以**数据版本、控制器、真实 segment 标识**为键，并按边界选择，而非季度桶。

本机研究产物是 `artifacts/rebuild-audit-probes.cjs` 与 `artifacts/rebuild-loader-probe.json`；它们被忽略，不作为未来测试的唯一依据。后续实现时应把该场景变成独立、可检入的契约测试。

### 已执行：当前 UTC 差值与 Eyes ET 不一致

直接运行恢复后的 `TimeUtils.unixToEt`，对 `2026-01-01T00:00:00Z`：

- 旧 `START_TIME` 算法：`820497600`。
- 恢复代码的 ET：`820497669.184`。
- 差约 `69.184` 秒。

此结论只说明当前两套算法不同。新系统要明确采用与目标源一致的 ET 边界、闰秒表及显示转换；不能把 `Date.UTC` 毫秒相减称为已完成天文时间转换，也不能无证据宣称已达到任意精度的 TDB/SPICE 时间实现。

### 已核对的其他边界

`rebuildTreeIfNeeded` 的自动播放检测只搜索 `segmentStart > treeEpoch && segmentStart <= simTime`；在 `setTimeScale` 接受负值而自动连续倒放时，跨越反向边界不会满足该条件。显式 `setTime` 会把 treeEpoch 置 NaN，故不能扩大称为“所有后退都错误”。新实现用每个实体的活动阶段索引变化判断，正放、倒放和跳转共用同一条路径。

`src/data/catalog.json` 有 844 项，恢复的 `EntityCatalog.json` 有 724 项；两者键集合各自独有 125 与 5 项。后者是内容元数据目录，前者混合了展开后的场景和控制器信息；单凭数量不能断言后者漏了 120 个天体。新 catalog 编译器必须联合 SceneInfo、内容目录、实体工厂和控制器配置，保留来源，不把某一个目录当作全部物理定义。

## 从分析到实现的最低门槛

每项功能必须有：源码定位、输入数据、输出/状态、副作用、单位/坐标/时间约定、资源所有者、失败与取消处理、实际验收场景。未知项保留为未知；上游已知缺陷不因“复刻”要求而自动复制。

第三方包的“理解”可以落实为已识别的职责、实际用到的 API、固定版本与可替换适配器，不要求把 Moment 的每个语言规则、每个压缩 codec 的内部汇编都重写成自研代码。自有业务逻辑不能以不透明恢复 bundle 代替；不同证据级别也不能混记为“全部分析完成”。

新系统设计见 [设计说明](../superpowers/specs/2026-10-16-controlled-solar-system-design.md)。用户已审阅并确认推荐路线；生产运行入口在新系统验收前不切换。
