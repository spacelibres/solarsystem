# 如何核对本轮真正完成的工作

本轮针对用户指出的短变量、压缩控制流与无效批量注释，直接修改 `eyes/` 中的可编辑源码。**结构索引覆盖整个工程，不表示整个工程已经完成语义分析。** 当前验收按文件记录在 [semantic-progress.json](semantic-progress.json)；每个已登记文件包含证据路径与当前源码 SHA-256，后续源码变化会使检查失败，必须重新核对。

v0.2.32 的范围为 299 个源码整理/契约验证文件、1 个部分匹配的 Three core，以及 732 个执行 AST 与上一版本一致的其余 JavaScript 文件。三者合计覆盖全部 1,032 个 JavaScript 文件的变更核对，**不是全部文件语义分析完成的证明**。另有模板、目录数据、说明、清单等非 JavaScript 文件；完整结构参考共登记 1,105 个 Eyes 文件。

## 阅读与维护顺序

1. 从 [PreloadManager 实际修改](preload-semantic-changes.md) 看用户提供的例子。DOM 节点、星层数量与事件处理都有具体名称；第二层星空从空节点修正为 24 颗星。
2. 看 [应用层](application-semantic-changes.md)：路由、视图、UI、管理器的绑定表及当前声明/使用证据。新名称是根据使用关系整理的维护名称，并不冒充被压缩前的原始名称。
3. 看 [动力学、地形与数学](dynamo-semantic-changes.md)：采样、时间和坐标约定、地形像素/网格插值及边界。
4. 看 [资源与核心](resource-semantic-changes.md)：引用计数、取消后到达的资源、实体生命周期、下载队列，以及保留的原有疑点。
5. 看 [五个故事](stories-semantic-changes.md) 与 [shader](shader-semantic-changes.md)：进入/退出时恢复状态和不改变运行时 GLSL 的可读性整理。
6. 用 [总参考](README.md) 查每个文件、类、方法的当前签名、行号、依赖与操作证据。架构文件保留初始研究背景；当前逐文件参考优先采用源代码中的说明。

## 哪些检查能说明什么

| 检查 | 可以支持的结论 | 不能替代的工作 |
| --- | --- | --- |
| 冻结词法规范化哈希 | 允许局部绑定重命名及已列出的弃值控制流展开，保留常量、公开属性、自由变量和操作结构 | 函数 `.name`、源码反射、任意引擎下的全部语义证明 |
| 实际模块 CPU 检查 | 被列出的算法样本、状态转换、资源释放与异常分支符合预期 | 所有输入、GPU 驱动和交错生命周期的穷尽证明 |
| shader 导出哈希 | GLSL 运行时字符及材质配置没有改变 | 全场景视觉比较 |
| 文件 SHA 与文档新鲜度检查 | 当前索引和验收证据对应当前源码 | 自动推导真实业务语义 |
| 未验收文件的冻结 AST 检查 | 清除模板注释没有夹带修改剩余模块的执行结构 | 证明这些模块已完成语义分析 |
| 浏览器检查 | 当前环境中首页、地球、暂停/恢复、旅行者故事进入与退出可执行 | 全浏览器、全对象与全部故事验收 |

原本存在的 Collection、FPS、资源共享、异步瓦片等疑点在分领域文档中明确列出，没有用重命名掩盖，也没有未经验证夹带修复。第三方库的官方来源匹配另行记录，仍未确认的部分保持待验收状态。空样式恢复模块、模板、数据与构建支持文件也不能因出现在索引中就自动记为语义分析完成。


## v0.2.33：结合实际 Three 源码的深入分析

v0.2.33 的验收清单记录 299 个已做列明重构/行为检查的文件、14 个部分上游匹配文件，以及 719 个保留执行 AST 的其余 JavaScript 文件，共 1,032 个 JavaScript 文件。完整结构索引仍是 1,105 个 Eyes 文件；此分类不表示 1,105 个文件的语义均已完成。

本轮直接对照官方 npm Three 0.185.0 与 0.185.1，而非根项目安装的 0.186.1。恢复应用的 REVISION 为 185；现有证据不能区分两个补丁版本。以下文件把源码改名、结构对应和人工语义判断分别列出，不能把对应数量等同于全部工程已分析完成：

- [core 对照](three-core-next.md)：方法、辅助函数和嵌套类的覆盖范围、实际改名数、匹配规则、完整词法证明与每个未匹配方法的具体结构差异。
- [剩余语义](three-core-remaining-semantics.md)：未取得完整结构匹配的方法及辅助函数的实际输入、结果、状态、算法与边界；最近候选名称不作为身份依据。
- [renderer 与 addon](three-renderer-next.md)：整声明严格匹配与 addon 参数角色推断分开；142 个 ShaderChunk 和 16 个 addon shader 字符串保持原样。
- [Eyes 接缝](eyes-three-integration.md)：34 个渲染组件、实体到 Three 的坐标与帧流程、+Y 前向投影、手动矩阵和资源所有权。

本轮的行为修复明确限定为 ThreeJsHelper 的 Points/Line 几何释放，以及递归和批量销毁时传递 GL 上下文。其余整理保留词法规范化后的执行结构。新增检查既验证这两个实际缺陷，也验证投影、事件、动画、几何、缓冲区和部分 loader 的 CPU 契约；不覆盖全部 GPU、XR 或外部 decoder 路径。

独立审查还发现并修复了两类分析工具问题：同名嵌套函数声明的绑定归属，以及匹配时对遮蔽 undefined、块级声明和空返回的过宽规范化。负例先复现再验证，原始与修改后实际 core 的全量词法摘要仍一致。匹配工具只在显式研究命令中运行，普通开发和构建不生成或覆盖 recovered 源码。

v0.2.33 已在 Windows / Node 24.15.0 下重新完成 `npm ci`、`npm test`（226 项 Vitest + 229 项 Node 检查，共 455 项）、`npm run check` 和 `npm run build`。生产服务实际重新加载地球，切换到月球并返回地球，浏览器控制台未见 error。此浏览器范围只代表这次启动与对象切换。

## 再次编辑时

上一里程碑 v0.2.32 在 Windows / Node 24.15.0 下完成 `npm ci`、`npm test`（226 项 Vitest + 214 项 Node 检查，共 440 项通过）、`npm run check` 与 `npm run build`。版本脚本集成测试的 Node/npm 启动曾超过默认 5 秒；现为这两项测试显式设置 20 秒限时、子进程 15 秒限时，版本断言没有删改。最终构建也在浏览器重新打开首页与地球，控制台未见错误；暂停/恢复和旅行者故事进入/退出另有实际交互检查。

- 正常修改 `eyes/`，不要运行恢复工具覆盖源码。
- 执行 `npm test`、`npm run check`、`npm run build`。测试从检入的冻结基线与小型真实数据夹具运行，不依赖本机临时研究快照。
- 修改已登记的文件后，先核对既有约定与新的行为，再更新验收清单的 SHA 和相关说明，最后运行 `npm run eyes:analyze` 更新当前参考。
- 分析命令只写文档；旧批量注释命令会明确拒绝执行。源码注释必须针对实际约定、原因或边界，不再铺设模板式完成标记。
