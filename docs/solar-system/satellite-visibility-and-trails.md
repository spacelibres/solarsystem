# 卫星显示、轨迹与缩放性能（0.2.38）

本页保留该版本记录；其分段 LineMaterial 实现已在 0.2.39 被连续线带替换，
最新轨迹、近景精度和图层规则见 [连续拖尾修正](continuous-trails.md)。

## 问题及原因

此前总览只激活太阳、八大行星和月球。相机放大不会改变激活名单；
行星近景又只展开天然卫星，导致已存在目录中的地球人造卫星没有显示。
目录有 148 个 Earth + spacecraft 分类对象，并非所有对象都有当前星历。

此外，渲染循环每帧复制 842 对象的状态，重复重建行星轨道并上传几何。
卫星的 `orb` 数据被误画为完整椭圆，其余轨迹只截取当前数据叶，且每日才刷新。

## NASA 源码依据

- `eyes/src/engine/managers/SceneManager.js:213`：父天体系统的投影半径达到
  20 像素后激活子对象。系统半径优先使用 `systemRadius`，否则为半径的 25 倍。
- `eyes/src/engine/managers/TrailManager.js`：只有八大行星和地球的 Moon
  使用闭合 OrbitLine；其他卫星和航天器使用随时间移动的 Trail。
- `eyes/src/engine/core/Unidentified708.js`：ISS 历史轨迹长度为 5573 秒，
  Hubble 为 5748.5 秒。不能用瞬时轨道周期替换明确配置。
- `eyes/src/engine/components/TrailComponent.js`：自动长度来自位置、速度和
  轨道能量；初始步长为长度的 1/120，速度转角超过 3° 时细分。
- `eyes/src/engine/core/TrailShader.js`：默认宽度由 0 到 2 像素，尾部
  透明度由 0 到 1，相加混合；悬停宽度 2 到 4 像素，透明度为 1。

这些是恢复源码中的类名，不表示找回 NASA 未公开工程或全部原始变量名。

## 自有实现

- `navigation.ts` 按当前 ET 的实际 parent 展开子对象，不使用历史发射地分组
  代替当前归属。行星近景直接包含人造卫星，相机缩放按上述投影规则自动展开。
  太阳的投影系统也展开日心航天器；小天体图层保持源端默认关闭，可从目录单独查看。
- `render-world.ts` 增量更新可见对象，保留相机、已有模型、纹理与轨迹。
  退出显示范围才释放对应资源；网络和模型并发仍受资源池限制。
- `domain/trails.ts` 跨连续 `.dyn` 叶采样真实星历，保留精确当前端点；遇到
  数据缺口或父参考体切换停止连接。默认最多 1025 个样本，细分上限 20 次。
- `render/trail-material.ts` 在官方 Three.js LineMaterial 中加入索引渐变和宽度
  渐变，使用原始 trail 颜色。卫星历史轨迹整体平移到父天体当前的位置。
- `ExplorerRuntime.renderFrame/tickForRender` 提供内部只读借用数据，公共
  `snapshot()` 继续返回独立副本。暂停不重复求值，相同激活集不重启请求。
- 行星轨道在端点运动不足 1/4 CSS 像素时复用几何；相机单独缩放不再重算
  全部椭圆。几何更新计数和 FPS / CPU ms 可在“诊断”查看。
- 画布尺寸由 ResizeObserver 缓存，渲染循环不在修改标签后反复读取
  clientWidth/clientHeight，避免卫星较多时出现同步布局。
- 标签与 canvas 是兄弟节点，标签上的滚轮输入转交画布控制器，避免滚轮
  碰到名称时突然失效；不把整个标签层交给拖拽控制器，以保留点击选择。

## 验证与边界

真实数据 ET 845466600 下，单独展开地球请求 111 个对象，88 个就绪，其中
76 个航天器；ISS、Hubble、Aqua、Terra 均有有限坐标且 parent 为 earth。
木星请求 112 个对象全部就绪，Io、Europa、Ganymede、Callisto 的 parent
均为 jupiter。全局行星/月球及参考体也计入请求和就绪数。

当前时间没有覆盖的任务不生成假轨道。TESS 的重复时刻冲突、GRACE-FO 的
控制器依赖环、Juno 的部分姿态冲突仍需独立分析；不代表其位置一概不可用。
自动展开日心航天器后，也显露了 BioSentinel、Europa Clipper、JUICE、
OSIRIS-REx、STEREO Ahead 的重复时刻解析，以及 Lucy 姿态索引解析缺口。
这些是当前解析器尚未接受的真实源数据，不能据此断言 NASA 数据损坏。
跨父天体和旋转参考系的历史轨迹暂时截断并写入诊断，尚未完整移植源端参考系转换。
自适应采样采用有界异步批次，而非 NASA 每帧四个端点的逐步填充调度。

性能数字只说明测试机器和场景；不能据此保证所有设备帧率。
最终本机生产总览观察到约 144 FPS、每帧 CPU 约 1.9 ms；同一 1280×720
地球卫星近景暂停场景，尺寸缓存修正前约 32.9 FPS / 26.01 ms，修正后约
142–143 FPS / 2.38–2.59 ms；实时运行约 115 FPS / 4.12 ms。
842 对象、1000 次暂停采样的同机基准，从公共逐帧
复制路径的 654.54 ms 降至内部渲染路径的 0.70 ms；它不包含 GPU 绘制时间。
单元测试覆盖只读数据复用、暂停、当前 parent、投影阈值、跨叶缺口、
源轨迹长度、自适应转角和已安装 Three.js shader 的实际替换点。
